# WarForz Lands implementation and verification report

Date: 2026-08-07

## Outcome

The undeployed contract and frontend were generalized to the authoritative mechanics in `WARFORZLANDS_MASTER_SPEC.md`. The source now compiles to WAX-compatible WASM/ABI with Antelope CDT 3.1.0, all 57 declared actions match their definitions, and the frontend production build passes.

This is suitable for a controlled WAX testnet deployment. It is **not approved for mainnet** until the live oracle/AtomicAssets/token permission tests, economic simulations, and an independent security audit are complete.

## Smart-contract changes

- Implemented authoritative Miner, Equipment, Land, Mining Type, land/miner match, Slot Unlock, and selector-based Free Play configuration.
- Added full admin CRUD and deletion/reference guards. Live custodied template counts prevent deleting or changing configuration still used by NFTs.
- Added mining-type selection, compatibility checks, land/miner match bonus, equipment modifiers, independent failure/death rolls, cooldown/health/durability damage, and configured NFT mint drops.
- Snapshotted every economic and destructive mining term before requesting randomness. Resolution does not reinterpret a pending request using later admin edits.
- Split the checksum into non-overlapping 64-bit lanes for failure, death, and NFT-drop rolls.
- Replaced the legacy internal Gold counter with configured NFT custody/mint behavior and renamed fungible withdrawal to `wdrawft`.
- Added a funded `rewardpool` with reservations. Mining and crafting cannot create unfunded FT liabilities, and concurrent pending requests cannot reserve the same funds.
- Snapshotted crafting result rules, reserved the maximum FT result, released unused reserves, and reference-counted rules attached to recipes.
- Added bounded deposits, batch/input caps, sequential slot unlocks, strict fee validation, referral-cycle bounds, oracle-only callback authentication, self-authenticated logs, maintenance/ToS/auth guards, and real AtomicAssets burns on destructive paths.
- Added Ricardian source descriptions for all public actions. CDT 3.1.0 still emits association warnings for the Markdown resource format; this is recorded as a packaging warning, not a C++/ABI failure.
- Added a reproducible CDT Docker image and stronger static security checks.

Physical EOS-safe identifiers differ from long conceptual spec labels: `miningtypes` (`miningtypeconf`), `landminmatch` (`landminermatch`), `fpselectors` (`fpselectorconf`), `matchset/matchdel`, and `fpselset/fpseldel`.

## Frontend changes

- Added an admin-only dashboard with safe maintenance/slot/mining controls and an ABI-encoded advanced CRUD console covering every configuration action. Advanced writes require an explicit browser confirmation.

- Clarified Vault liquidity when testnet WAX is temporarily configured as the Silver token: duplicate WAX presentation is suppressed and the transferable `eosio.token::accounts` amount is explicitly labelled **Liquid WAX**, excluding CPU/NET stake.
- Corrected mining lifecycle timing. The `mine` action now creates only a temporary ORNG replay/busy lock; it no longer starts miner or land cooldown before a reward exists. On the authenticated ORNG callback, the contract atomically credits the reward, applies health/durability changes, starts the miner/land/equipment cooldowns together, detaches the miner and equipment, emits `logmine`, and deletes the pending mine. The frontend labels the brief oracle interval **Resolving reward** rather than presenting it as a long-running mine.
- Added the admin-only, maintenance-only `resetuser` test-reset action. It preserves all game configuration/content and reward-pool funding while removing one player's registration, ToS acceptance, balances, Gold, slots, activated lands, miners, equipment, cooldowns, deposits, craft state, occupancy, referrals, and block record. Physical deposited/miner NFTs are returned and in-game FT is refunded without a fee; already-burned activated Land/Equipment records are deleted. During an explicit factory reset, pending mine/craft reservations are returned to the reward pool and their ORNG associations are cancelled; any delayed callback is rejected as an obsolete unknown ID. Resets remain per-account/batch-bounded for WAX CPU safety.
- Added the guarded `wipeall` testnet factory-reset action. It requires contract authority, maintenance mode, zero registered users, zero pending ORNG associations, and zero NFT custody/template usage. Given the explicit Smithy recipe scopes, it erases all global configuration, templates, display metadata, mining types, matches, slots, selectors, recipes/rules, craft counters, ToS content, referrals, block records, and free-play state. The remaining accounted reward pool is returned to the configured fee account before reward/FT/NFT/main configuration singletons are removed. Contract code and ABI remain deployed so configuration can be rebuilt from scratch.
- Added `scripts/seed-config.sh`, a single complete fresh-deployment configuration seeder with guarded `testnet` and `mainnet` profiles. It validates the exact WAX chain ID and required accounts, refuses non-empty deployments, requires explicit `CONFIRM_MAINNET=YES`, contains no keys, keeps maintenance enabled, and loads global/FT/NFT/ToS configuration, four Miner tiers, three Equipment tiers, paid and Free-play Lands with metadata, Normal Mining, four slot rows, hourly Free-play weights, and all 13 deterministic Smithy recipes. Major deployment values and template IDs are environment overrides; mainnet additionally refuses the disposable test treasury default. Reward funding, `fpstart`, permissions, and maintenance-off remain deliberate post-verification operations.
- Made configuration seeding safely resumable after a partial RPC/wallet interruption. `SEED_RESUME=YES` permits reviewed upserts, Smithy recipes now detach an existing recipe before deleting/recreating its referenced rule, every submitted action prints its payload, and `CLEOS_TIMEOUT` (45 seconds by default) turns a stalled endpoint into an explicit error instead of leaving the script apparently frozen at `ruleset`. The standalone Smithy helper uses the same bounded, visible transaction behavior.
- Fixed the maintenance gate's white-on-cream copy by assigning an explicit dark ink color to the parchment panel and high-specificity dark brown/orange colors to its eyebrow, heading, and explanatory text. This prevents the global white display-heading theme and generated utility ordering from making maintenance information invisible.

- Implemented economy configuration V1 (`WARFORZLANDS_ECONOMY_CONFIG_V1.md`) in the contract and seeder. The Gold drop chance is now **additive** across miner, equipment, land and mining type rather than multiplying the miner rate by the equipment boost, so V1's own worked examples hold (Common miner 5.00% + Common equipment 2.50% now yields 7.50%, not 5.125%). `landconf` gained `nft_drop_bonus` so premium Land contributes Gold chance at all, and `config` gained an admin-set `max_nft_drop_rate` enforcing the V1 §8 global ceiling instead of the previous 0–100% clamp.
- Moved per-mine health damage onto the miner. `minerconf.health_cost_per_mine` carries V1 §5's −5 to −30 HP per rarity, and the mining type's `health_cost` became a multiplier on it, so a future dangerous mine still scales damage without needing one mining type per miner tier.
- Added in-game Gold as a craft input. `craftrecipe.gold_amount` plus the admin action `recreqaddgld` price recipes in Gold, and `craft` debits the player-scoped `goldbalance` in the same transaction as the FT and NFT inputs. Gold could not previously be charged at all: it is burned into a counter on deposit and never creates a `deposits` row, so the existing `ReqNFT` path was structurally unable to express it. The physical action name is the length-safe `recreqaddgld`, following the `landminmatch`/`fpselectors` convention.
- Land durability is now consumed only by a successful mine, matching V1 §2. A failed or fatal mine still costs health, cooldown and equipment durability. This was previously latent because every configured mining type has zero failure and death chance.
- Raised `MAX_RARITY` from 5 to 6 for V1's six miner tiers. `rarity` is descriptive ordering only — no reward, drop or damage term reads it — so the widened bound cannot shift game math.
- Rewrote `scripts/seed-config.sh` to V1 values with section references: flat 200 health and 3,600s cooldown (7,200s for Artifact), base FT 27/55/85/120/155/195, the deliberately inverted Gold curve of 0.50%/5%/4%/3%/2%/1.50%, flat 5 FT per HP healing, 125-use equipment at 1.35×–2.60× with falling Gold points, Land at 75/300/600 uses and 1.10×/1.12×/1.15× with +1.00%/+1.00%/+1.25% Gold, the six-tier free-play pool weighted out of 10,000, and every craft priced in Gold + FT. FT amounts are now rendered at the configured symbol precision instead of hardcoded 8-decimal strings.
- Made the seeder refuse to run when the Artifact Miner, Legendary Miner, Epic Equipment or Legendary Equipment AtomicAssets templates have no id configured, since the contract cannot detect a template that does not exist. `ALLOW_MISSING_TIERS=YES` seeds the remaining tiers with an explicit incomplete-economy warning; mainnet refuses it outright.
- Updated the frontend to the same economy. Reward previews use the additive capped Gold formula and read `config.max_nft_drop_rate`; mining preconditions multiply the miner's damage by the mining type; equipment "NFT Luck" renders percentage points at two decimals instead of rounding 2.50% to 3%; and the Smithy shows each recipe's Gold price, validates it against the `goldbalance` singleton, and blocks crafting with an explicit shortfall message.
- Verification: CDT 3.1.0 compiles to WASM/ABI with only the known Ricardian packaging warnings, static checks pass at 65 actions, the regenerated ABI carries `max_nft_drop_rate`, `health_cost_per_mine`, `nft_drop_bonus` and `gold_amount`, frontend `tsc -b` and Vite production build pass, and all six V1 §10–11 worked examples reproduce exactly. Nothing has been deployed or seeded on-chain.
- Confirmed the free-play design at product direction: free-play Land still requires the player to own a Miner, and RNG decides which Miner types are eligible, drawn across Artifact through Legendary from the configured `minerconf` tiers. The existing hourly ORNG rotation therefore stays, and the seeder now weights all six tiers instead of four.
- Enforced that a free-play selector can only name a miner type that exists in `minerconf`. `fpselset` rejects an unknown type and `minerdel` refuses to remove the last template of a type a selector still references. Without both guards an admin could weight a tier no player is able to own, and the window it won would lock every player out of free-play until the next rotation.
- Made consumable decay a per-mining-type rule rather than a hardcoded one, at product direction that "there will be success only for normal mining type, there might be other mining type that might have different rules". `miningtypeconf.decay_on_failure` is snapshotted into the pending mine alongside the other economic terms; when false, a failed or fatal mine spends no Land durability and no Equipment uses. Normal Mining seeds it false, satisfying V1 §2 for Land and extending the same treatment to Equipment. Equipment cooldown and detachment still run on a failed mine, so a failure never strands Equipment attached to its Miner.
- Added a withdrawal-based referral at product direction: a referrer earns a configurable share of what their referee withdraws, via the new `ftconfig.referral_withdraw_pct`. The share is **carved out of the collected withdrawal fee**, never added on top, so a referred player receives exactly the same net amount as an unreferred one and the withdrawal creates no unfunded liability. `ftconfigset` bounds the rate to 5%, the floor of the hourly 5–9% fee roll, so the carve stays solvent whatever the roll produces; a second runtime clamp and an `is_account` check fold the share back into the platform fee rather than stranding it when a referrer is unusable. The pre-existing mining-reward referral (`config.referral_rate`) is retained and seeded to zero, so either mechanism can be enabled later without redeploying.
- Verified the referral split arithmetic across the whole 5–9% fee range: the referee's payout is byte-identical referred or not, the three payouts always re-sum to the withdrawn amount with no rounding leak, and the worst case (5% fee floor against the 5% maximum referral) leaves the platform share at zero without going negative.
